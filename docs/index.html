Appspresso

A production-minded Capacitor + Vite + React starter and a publishable library — one package for the backbone of mobile and web apps.

UI follows shadcn/ui patterns (Tailwind + cva). Client state Jotai, server state TanStack Query (persist), API Axios, routing React Router, native Capacitor 7.

Overview

Appspresso is both a runnable template (src/, demo/) and an npm package (appspresso with subpath exports from dist-lib/). You get a coherent mobile + web spine: bootstrap, providers, UI primitives, offline sync scaffold, auth adapters, deeplinks, IAP hooks, i18n, feature flags, and a small CLI — without assembling dozens of unrelated libraries yourself.

Requirements

  • Node.js 20+ (Capacitor 7 CLI)
  • Android: Android Studio + JDK
  • iOS: Xcode + CocoaPods
npm install
cp .env.example .env
npm run dev

Why one package

Mobile and web apps need routing shells, client and server state, HTTP, i18n, native bootstrap, optional offline storage, auth surfaces, forms, error handling, theming, and tooling. Appspresso puts the pieces that belong together under one dependency with versions that are already integrated and tested as a set.

  • Batteries included, one decision — Instead of a long “which library for X?” list, you add appspresso and optional peers (Firebase, Supabase, extra Capacitor plugins) only when you need them.
  • Simplest path to a working app — npm create appspresso, then runBootstrap(), AppspressoRootProviders, and import … from "appspresso/…". The scaffold and library share the same modules.
  • One version line, easier upgrades — Your product app mostly tracks "appspresso": "^x.y.z". Patch and minor bumps bring bootstrap order, provider stack, Vite preset, and Capacitor-oriented defaults that were validated together — not ten unrelated changelogs.
  • Granularity without fragmentation — Subpath exports (appspresso/sync/*, appspresso/components/ui/*) let you import only what you use, while still publishing and upgrading a single package.
  • Starter and library, same source — demo/ and create-appspresso stay in sync via npm run create:sync-template.
Upgrade Appspresso once — bootstrap order, provider stack, and Capacitor-oriented defaults move together instead of chasing ten unrelated changelogs.

Many small packagesFine-grained dependencies; higher integration cost and version skew across the stack.

Philosophy & principles

  • Production-minded hybrid — Ship from the template or consume dist-lib/ in an existing Vite app.
  • Capacitor + Tailwind UI — Native shell via Capacitor; UI is Tailwind + small primitives (Radix only where it helps, e.g. form Slot).
  • Clear state split — One Jotai appStore for client UI state; TanStack Query (+ persist) for server/cache.
  • Mobile-first defaults — base: './', splash/status bar, keyboard-aware tab shell, native SQLite + sync outbox path.
  • Opinionated defaults, optional depth — Core in the package; Firebase, Supabase, and some Capacitor plugins are optional peers.

Host-owned: lazy route tree and page composition stay in your app — not shipped inside the package so products keep full control of navigation.

Bootstrap & providers

runBootstrap() in src/app/bootstrap.ts runs before the UI is fully interactive:

  1. initTelemetry
  2. getEnvConfig → loadRuntimeConfig (merge VITE_FEATURE_FLAGS + optional remote URL)
  3. initAppearance (theme + status bar)
  4. initDatabase → updates sqliteStatusAtom
  5. initSyncLayer
  6. Splash hide last — launchAutoHide: false in project config avoids early auto-hide glitches

Project config

Central config via defineAppspressoProject in appspresso.config.ts — app id, display name, theme palette (HSL triples), splash, status bar. Capacitor JSON is emitted (e.g. npm run demo:cap-config → capacitor.config.json). 

import { defineAppspressoProject } from "appspresso/build/project-config";

export default defineAppspressoProject({
  app: {
    id: "com.example.myapp",
    displayName: "My App",
    theme: { palette: { light: { primary: "221 83% 53%" } } },
    splash: { launchAutoHide: false, backgroundColor: "#0f172a" },
  },
});

Package consumption

npm run build:lib   # in the appspresso repo → dist-lib/
import { Button } from "appspresso/components/ui/button";
import { runBootstrap } from "appspresso/app/bootstrap";
import { http } from "appspresso/api/http";
import { flushOutbox } from "appspresso/sync/sync.service";
  • Subpath exports mirror src/ — import only what you need.
  • Add ./node_modules/appspresso/dist-lib/**/*.js to Tailwind content.
  • peerDependencies declare React, Router, Jotai, Query, Capacitor plugins, etc. — install compatible versions in the host app.
  • Router / route-tree stays in the host app (product-specific lazy routes).

Upgrading

Bump appspresso in package.json (npm update appspresso). Read the package release notes for breaking changes. Re-run appspresso doctor and your test suite; check optional peer majors (Capacitor, Firebase) if you use them.
